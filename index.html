THE OPERATING PRINCIPLE

Observe causally. Decide once. Replay exactly. Fail closed. Reconcile externally.

Research asks whether a strategy would have worked.
Production assurance asks whether the live system behaved exactly as designed.
TORAM starts where the backtest stops.

THE PRODUCTION GAP

A strategy can pass research and still become a different system in live markets.

Live feeds arrive differently. Timestamps and event order matter. Quotes become stale. Connections break. Market depth changes while decisions are being made. Simulated fills differ from real fills. Broker state can diverge from local state. The production problem is not only whether the model is intelligent; it is whether the entire path remains trustworthy.

OBSERVE

What did the engine actually see?

Preserve the exact causal observations available at the decision moment.

TRUST

Was the state still safe to use?

Freshness, gaps, disconnects and reconnect boundaries determine whether execution is allowed.

REPRODUCE

Can the decision be replayed?

The same recorded causal history should traverse the same decision path later.

RECONCILE

What did the broker actually do?

Intent, acknowledgement, fills, positions and external truth remain distinct until reconciled.

WHY NOT A FREE BACKTESTER?

Use one. TORAM is solving a different layer.

Open research and backtesting engines are valuable. Some already use the same strategy code for backtest and live trading. TORAM is focused on the production assurance problem that remains after the strategy has been written.

Backtesting
